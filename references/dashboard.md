# Dashboard

A dashboard is for monitoring and decision support, not for decorating the home screen with metrics.

## Start with questions
For each element, define:
- what question does this answer?
- what decision/action follows?
- what time range and segment does it represent?

## KPI cards
Use only for important summary metrics.
Include context such as delta, baseline, target, or time range when meaningful.
Avoid a row of arbitrary numbers.

## Charts
Choose chart by analytical task:
- trend -> line/area
- comparison -> bar
- distribution -> histogram/box plot when suitable
- composition -> stacked bar; use pie sparingly
- relationship -> scatter

Make filters and time context visible.
Provide drill-down to evidence when users need to act.

## Operational dashboard
If the user needs to work, include queues, exceptions, alerts, tasks, or records—not only charts.
