# Review Checklist

Review the rendered product, not only the source code.

## Task
- Is the primary task obvious?
- Can the user identify the next action?
- Are frequent actions easier than rare actions?

## Hierarchy
- Is the most important information visually dominant?
- Is decorative content competing with operational content?
- Is grouping meaningful?

## Density
- Is the screen too empty for repeated work?
- Is it too dense for the target user?
- Can users compare records without excessive scrolling?

## Tables and lists
- Do columns support decisions?
- Are filters/sort/search discoverable?
- Are row and bulk actions clear?

## Forms
- Are fields ordered by workflow?
- Are validation and server errors recoverable?
- Is entered data preserved?

## States
Check realistic examples of:
- loading
- empty
- no results
- error
- long content
- large data volume
- disabled/permission state

## Responsive
Review at least:
- narrow mobile
- tablet/small laptop
- common desktop

Do not accept horizontal overflow or unreadably compressed controls unless intentional.

## Visual consistency
- spacing
- typography
- radius
- shadows
- icon style
- control heights
- status colors

## Final test
Ask: would a user who performs this task 100 times per day consider the interface efficient?
